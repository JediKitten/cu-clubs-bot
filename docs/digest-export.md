# Дайджест: текстовый пост и карточки

Сверка исходников: **22 ноября 2026**. Python-реализация входит в рабочий
выпуск `b6d4531` на прежнем сервере (совпадение модулей подтверждено отдельной
операционной сверкой). Код сервиса — `digest.py`, Telegram — `digest_ui.py`,
сохранение/удаление файлов окна — `screens.py`. Плагин и его ограничения —
[figma/digest/README.md](../figma/digest/README.md), код — `figma/digest/code.ts`.
Выкладка Python-кода не доказывает ручную приёмку каждой кнопки и версии плагина.

Администратор нового CU Clubs открывает «Админ-меню» → «Создать дайджест»,
выбирает неделю (понедельник–воскресенье по Москве), затем все открытые встречи
или ручной выбор. В ручном списке восемь встреч на странице; галочки сохраняются
при переходе к предпросмотру и обратно. Из одной проверенной подборки выдаются
два результата:

- «Текст поста»: жирные дни недели, стрелки со ссылками на встречи и названиями
  клубов, коллаборация «Клуб х Клуб», P.S. со ссылкой на «Анонсы ЦУ» и
  #Дайджестсобытий — по образцу владельца. Пустые дни пропускаются.
  Длинный пост показывается частями с сохранением ссылок; «Скачать пост целиком»
  отдаёт HTML-файл для открытия в браузере и копирования с форматированием.
- «Карточки · файл для Figma»: `cu-clubs-digest-YYYY-MM-DD.json` для плагина,
  который строит копию обложки/подробных карточек и точек календаря.

Оба результата содержат одни и те же клубные встречи CU Clubs. Остальные
категории исходного макета Figma сохраняются при перераскладке. Текст поста
не импортирует мероприятия иных источников. Автоматической публикации
в Telegram-канал нет.

Экспорт использует только базу текущего CU Clubs, без Google Sheets. Self-service
с другой БД не является источником рабочего дайджеста. Включаются открытые
`published` и исторические `held` встречи, как в публичной выдаче. Закрытые,
отменённые, черновые и ожидающие партнёра встречи не входят. Коллаборация — одна
встреча со всеми клубами. Неделя определяется по началу встречи в интервале
`[понедельник 00:00, следующий понедельник 00:00)` по Москве; продолжающаяся
с прошлой недели встреча повторно не включается. Порядок — начало, затем
стабильный ID; клубы в коллаборации сортируются по названию и ID.

Перед выдачей права администратора и сохранённые версии проверяются повторно.
Изменение/исчезновение выбранной встречи возвращает обновлённый предпросмотр;
для выбора «все» также проверяется появление новых встреч. Требуется повторное
подтверждение. Ограничения: 500 встреч, JSON-снимок не более 1 000 000 байт; превышение
даёт ошибку без обрезания данных. Превышение числа встреч сохраняет экран
выбора и галочки; ошибка размера файла или полей встречи сохраняет предпросмотр
с переходом к изменению подборки. Если имя нового бота не настроено, экспорт
останавливается. Выданный файл удаляется из чата при следующей навигации в этом
окне, включая замену новым файлом; сохранённая пользователем копия не удаляется.
На диске временный файл не создаётся. Автоматического срока удаления без
следующей навигации нет.

## Формат версии 1

```json
{
  "schema_version": 1,
  "timezone": "Europe/Moscow",
  "week_start": "2026-11-16",
  "events": [{
    "id": "stable-event-public-id",
    "version": 2,
    "visibility": "open",
    "status": "published",
    "starts_at": "2026-11-16T18:00:00+03:00",
    "ends_at": "2026-11-16T20:00:00+03:00",
    "clubs": [{"id": "cinema", "name": "Киноклуб"}],
    "title": "Встреча киноклуба",
    "description": "Публичное описание встречи",
    "room": "B310",
    "public_url": "https://t.me/new_cu_clubs_bot?start=e_stable-event-public-id"
  }]
}
```

`id` — постоянный `Event.public_id`, `clubs[].id` — `Club.public_id`.
Имя бота и ID в примере иллюстративные: сервис строит URL из реального
`CU_CLUBS_TELEGRAM_BOT_USERNAME`, а не из константы примера.
Время имеет явное московское смещение. `room` содержит публичную аудиторию,
внешнее место или «Онлайн» с публичным описанием подключения; для ещё не
назначенной аудитории допустима пустая строка. Поля выбираются
явно: нет ФИО/контактов участников, списков регистраций, ключей API,
`post_registration_text`, закрытых ссылок и произвольных полей модели. Публичные
названия/описания/места переносятся как авторский контент карточек; это не
автоматический фильтр персональных данных внутри введённого автором текста.
`public_contact` в JSON версии 1 не включён: контакт есть в карточке/ICS,
но формат дайджеста содержит только перечисленные поля.

в этой сверке тесты и Figma не запускались. Нужно проверить живые выдачу

обложки и Graphik LC Regular/Medium; Inter выбирается явно для черновика.

на реальном редакторском макете остаётся обязательной до публикации выпуска.
Публикация в канал выполняется редактором отдельно; бот и плагин её не делают.
