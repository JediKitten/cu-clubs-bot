# Контракт календаря клубов

Сверка кода: **22 ноября 2026**. Адаптер находится в `calendar.py`,
`integrations/sheets.py`, `calendar_models.py`, административный интерфейс —
`calendar_ui.py`. Исходное исследование шаблона выполнено 12 ноября; его
снимок сохранён ниже. [Выпуск 14 ноября](release-2026-11-14.md) — исторический
отчёт, а не текущая гарантия работы Google. Целевой контракт шире реализации.

## Реализовано и границы передачи

Отдельная операционная сверка 22 ноября подтвердила выкладку Python-модулей
на прежнем сервере и настройки `calendar_sync_enabled=true`,
`calendar_allow_writes=true`, OAuth, наличие файла credentials и совпадение
выбранной книги с разрешённой тестовой копией. В этой сверке обращения к Google
не было: существование файла и значения флагов не доказывают действительность
refresh token, права на книгу или успешную запись.

| Область | Текущее поведение исходников |
|---|---|
| Выбор года | `Calendar YYYY` по московской дате начала; автоматического создания вкладки нет |
| Чтение | Свежая metadata и `B1:H{count}`, максимум 2000 строк; служебные вкладки вне записи |
| Слоты | Семь числовых последовательных дат, понедельник, граница по следующему заголовку; последний блок без следующего заголовка даёт `unbounded_week` |
| Идентичность | Метка `[cu-clubs:event=<public_id>]` в note + ссылка на встречу; `calendar_bindings` хранит baseline/координаты/версию/ошибки |
| Запись | До двух целевых ячеек за операцию; только значение и note, без изменения формата; перенос освобождает только свою прежнюю ячейку |
| Ручные правки | Аудитория сверяется в обе стороны; для опубликованной встречи обновляется версия и создаётся уведомление; прочие изменения текста/метки/даты дают конфликт |
| Статусы | `published`/`held`; `cancelled` обрабатывается только при существующей привязке, карточка помечается отменённой |
| Дайджест | Читается фактический цвет `#FF00FF`; первая сверка и первая сверка новой недели без исторической рассылки, затем уведомления лидерам с дедупликацией неделя–встреча–получатель |
| Ошибки | `pending/synced/conflict/error` доступны в «Админ-меню → Календарь»; решение room-конфликта, повтор и ввод аудитории проверяют актуальное состояние |

`guarded_write` перечитывает ячейки и проверяет результат. Для замены текста
одной непустой ячейки при неизменной note применяется точный `findReplace`.
Это не общий атомарный compare-and-swap: вставка, изменение note и перенос
сохраняют окно для параллельной человеческой правки. Ячейки с rich text или
ссылкой в `userEnteredFormat.textFormat` требуют ручной проверки и не
перезаписываются. Полного сохранения любых конкурентных правок код не гарантирует.

Не реализованы создание годовой вкладки, расширение недельной сетки и UI
«Указать ячейку»: при отсутствии года, ограниченной недели или безопасного
слота администратор исправляет шаблон вручную и повторяет сверку. Полнота года,
визуальное соответствие исходной книге и восстановление после реального сбоя
Google остаются отдельной приёмкой. Текстовый/JSON-дайджест из БД — другой
механизм: он не читает Sheets и не меняет цвета, см. [digest-export.md](digest-export.md).

## Источники и конфигурация

Реальные идентификаторы, закрытые ссылки и credentials находятся вне репозитория.
Приложение читает следующие ключи с префиксом `CU_CLUBS_`:

| Ключ | Назначение/значение по умолчанию |
|---|---|
| `GOOGLE_SPREADSHEET_ID` | Единственная выбранная книга |
| `GOOGLE_CREDENTIALS_PATH` | Путь к закрытому OAuth authorized-user JSON |
| `CALENDAR_SYNC_ENABLED` | Включение сверки, по умолчанию `false` |
| `CALENDAR_ALLOW_WRITES` | Явное разрешение записи, по умолчанию `false` |
| `CALENDAR_TEST_SPREADSHEET_ID` | Должен точно совпадать с выбранной книгой для записи |
| `CALENDAR_SYNC_INTERVAL_SECONDS` | Интервал фонового цикла, по умолчанию 60, допустимо 15–3600 |
| `CALENDAR_SYNC_BATCH_SIZE` | Максимум встреч за цикл, по умолчанию 10, допустимо 1–50 |

Запись разрешена кодом только при `CU_CLUBS_ENVIRONMENT=test`, явном разрешении
и совпадении книги с тестовой. Это не разрешение подключать рабочую книгу или
менять правила её защиты. Реальный тестовый контур может отправлять Telegram
уведомления; для автономной репетиции внешнюю доставку отключают отдельно.
`GOOGLE_SHEET_NAME` не выбирает год в этом адаптере: название строится как
`Calendar {year}`. Настройка `CALENDAR_DIGEST_COLOR` объявлена, но текущая
`digest_color()` использует фиксированный RGB `#FF00FF`; другой цвет настройкой
пока не включается. Конфигурация сама по себе не является приёмкой интеграции.

Требование владельца продукта: сохранять исходный шаблон и использовать отдельную годовую вкладку `Calendar YYYY`. Остальные вкладки книги сохраняются и не используются как место для служебной информации бота.

## Исторический снимок структуры, 12 ноября 2026

При исследовании нативная книга имела локаль `ru_RU`, часовой пояс `Europe/Moscow`
и пять вкладок. В копии были сохранены их порядок, названия, идентификаторы
вкладок, размеры сеток и объявленные замороженные строки. Повторной живой
проверки этих размеров и содержимого 22 ноября не выполнялось.

| Вкладка | Размер сетки | Замороженные строки | Роль для адаптера |
| --- | --- | --- | --- |
| `Calendar 2026` | 877 строк × 12 столбцов | 3 | Календарная сетка |
| `Лист8` | 1000 × 26 | Не объявлены в metadata | Вне области записи |
| `Лист7` | 1000 × 26 | Не объявлены в metadata | Вне области записи |
| `Лист9` | 1000 × 26 | Не объявлены в metadata | Вне области записи |
| `регулярные встречи до конца года` | 1002 × 26 | Не объявлены в metadata | Вне области записи |

`Calendar 2026` устроен следующим образом:

- `B:H` — понедельник–воскресенье; подписи дней на английском проверены в строках 3 и 7.
- `J` — `comments`, `K` — `curator/producer`. Эти столбцы не принадлежат адаптеру.
- `A`, `I`, `L`, первые строки, повторные заголовки и вспомогательные области не считаются местами для событий.
- В `B4` находится заголовок образца, в `B5` — многострочный образец с восемью полями: клуб, название, время, аудитория, Толк, микрофоны, почта, ссылка. Образец не является событием.
- Строка недельных дат содержит настоящие числовые значения дат. В проверенных блоках понедельник задан числом, следующие дни — формулами вида `=B225+1`, `=C225+1`. Формат отображения `dd"."mmm` не содержит год. Даты нужно определять по вычисленному значению и типу, не по локализованной строке.
- В столбце `B` обнаружены 44 строки недельных дат: первая — строка 8, понедельник 2 февраля 2026 года; последняя — строка 250, понедельник 30 ноября. Проверенная последняя неделя включает воскресенье 6 декабря. Расстояние между соседними строками дат меняется от 2 до 11 строк.
- Примеры расположения недель: 2–8 ноября — строка дат 225, следующая строка дат 231; 9–15 ноября — строка 231, следующая 240. Координаты описывают снимок и не являются постоянными адресами API.
- Проверены эффективные цвета `#FF00FF` у заполненных карточек ноябрьских недель и `#EAD1DC` у октябрьских карточек. Сам цвет не доказывает, что ячейка является встречей. Строки дат имеют отдельную заливку `#FFE599`.
- Реальные карточки — неоднородный многострочный текст. Нельзя предполагать одинаковое количество строк или искать аудиторию по фиксированному номеру строки.

Название годовой вкладки не гарантирует наличие всех недель года. В текущем снимке не обнаружены датированные недельные заголовки января и после недели 30 ноября. Пустая область за последним заголовком не считается готовой календарной неделей.

## Что было проверено у копии 12 ноября

Metadata исходной книги и копии совпала по пяти вкладкам, кроме отдельного названия самой книги. Выборочные ответы `CellData` совпали целиком по запрошенным полям: значения, вычисленные значения, формулы, отображаемые значения, пользовательский и эффективный формат, заметки, ссылки, проверки данных и фрагменты форматированного текста, когда эти поля присутствовали.

Сравнены ограниченные диапазоны:

- На всех пяти вкладках — `A1:L12`.
- На календарной вкладке дополнительно — `B217:L251` и `B860:L877`.
- На трёх вкладках с общими названиями — `A495:L500`.
- На вкладке регулярных встреч — `A995:L1002`.

В верхних и средних выборках трёх вкладок с общими названиями значения не возвращались; это не является доказательством пустоты всей вкладки. Проверка выборочная: полное равенство книги, высоты строк, ширины столбцов, объединения, защиты и ветки пользовательских комментариев отдельно не удостоверялись. Отсутствие заметок в образце не разрешает будущему адаптеру перезаписывать заметки.

Содержимое людей, встреч, контактные данные и закрытые ссылки не копируются в этот документ, тестовые фикстуры или журналы. Фикстуры будущих тестов должны быть синтетическими.

## Целевой алгоритм и требования к дальнейшей доработке

Это требования владельца к полному адаптеру. Реализованную часть и пробелы
нужно читать по таблице в начале документа; пункты ниже не обещают наличия
всех перечисленных кнопок, гарантий конкурентности или автосоздания года.

1. **Разрешить год и вкладку.** По московской дате начала выбрать `Calendar YYYY`, получить свежую metadata и точное имя вкладки. В БД хранить идентификатор вкладки и книги; координату использовать как подсказку. При отсутствии нужного года или недели создать задачу администратора, не записывать в случайную пустую область.
2. **Построить карту недель.** Читать ограниченные области дат и вычисленные числовые значения. Подтвердить семь последовательных дней `B:H`, соответствие году и структуре шаблона. Граница блока — следующий достоверный заголовок дат с учётом разделителей. Заголовки, образцы, служебные записи, формулы и объединённые/защищённые области исключить из доступных слотов. Не использовать постоянную высоту недели.
3. **Найти существующую привязку.** Проверять служебную метку встречи в заметке вместе со ссылкой и записью `sheet_binding`. Метку добавлять к заметке с сохранением человеческой части. Поиск по координате без проверки идентичности недостаточен. Исторические карточки без надёжной привязки автоматически не присваивать новому событию.
4. **Поставить новую карточку.** Только после фиксации публикации в PostgreSQL worker находит подтверждённо свободный слот дня и перечитывает его перед записью. Не заменять формулу, чужой текст или служебную запись. Если свободного безопасного слота нет — «Указать ячейку / Повторить» и задача администратору. Самостоятельное расширение существующей недельной сетки не является поведением по умолчанию.
5. **Сохранить исходный шаблон.** Изменять только управляемые поля своей карточки и служебную часть заметки. Сохранять фон, формат текста, ссылки, пользовательские заметки и комментарии; не очищать строки, диапазоны дня или всю вкладку. Не выполнять массовую нормализацию старых карточек.
6. **Сверять аудиторию.** Раз в минуту сравнивать актуальное значение Sheets и БД с общим последним подтверждённым снимком. Совпавшее изменение применять один раз; разные правки одного поля и нераспознанный текст оформлять как конфликт с обеими версиями. Из Sheets принимать только согласованные обратные поля: аудиторию и признак дайджеста. Дата, название и прочие ручные изменения не должны молча менять доменную встречу.
7. **Обрабатывать перенос.** Сначала подтвердить собственную метку, исходный слот и доступный целевой слот. После подтверждения новой записи освободить только собственную управляемую часть прежней ячейки. Ручной перенос или неоднозначное совпадение передавать администратору. Удаление карточки не отменяет встречу в БД.
8. **Распознавать дайджест.** Читать `effectiveFormat`, нормализовать RGB. Рабочий цвет — `#FF00FF`; `#EAD1DC` не распознаётся до отдельного подтверждения. Учитывать только достоверно распознанные карточки встреч; цвет образца, служебной ячейки или заголовка не считается отметкой. При первом подключении заполнить состояние недель без исторических сообщений. Новая отметка уникальна по паре неделя–встреча; повторное чтение и сдвиг строк не создают повторов.
9. **Подтверждать результат записи.** После неопределённого исхода или тайм-аута искать уже записанную метку до повторной вставки. Вести версии, подтверждённый снимок и ошибки в БД. Недоступность Sheets не закрывает запись на событие. Сетевой повтор не должен создавать вторую карточку.
10. **Доставлять уведомления отдельно.** Реальное изменение аудитории создаёт одну операцию доставки уникальному объединению записанных и лидеров. Собственная запись адаптера не создаёт новое изменение при последующей сверке. Ошибки листа, отставание и конфликты доступны администратору.

При дальнейшей доработке записи необходимо проверить конкурентную правку
между перечитыванием и отправкой изменения. Существующие перечитывание и
проверка результата не устраняют это окно; его нельзя описывать как атомарную
защиту от любой потери человеческой правки.

## Новая годовая вкладка — ещё не реализовано

- `Calendar YYYY` создаётся как отдельная вкладка той же книги, с сохранением вида и структуры утверждённого шаблона. Существующая годовая вкладка и четыре прочие вкладки не пересоздаются и не очищаются.
- Перед созданием проверяется существование вкладки с этим именем. Повтор задачи не создаёт второй год и не заменяет найденную вкладку.
- Новый год получает недельные блоки, покрывающие все даты с 1 января по 31 декабря, включая неполные граничные недели. Формат `B:H`, вспомогательные столбцы, замороженные строки, образец, оформление и формулы сохраняются по шаблону.
- Даты предыдущего/следующего года могут отображаться в граничной неделе, но событие записывается только на вкладку года своей московской даты начала. Это предотвращает две карточки на границе лет.
- Нельзя просто скопировать историческую вкладку с реальными карточками и метками: при подготовке очищаются только распознанные области событий нового шаблона, затем задаются даты и проверяются формулы. Исторические встречи, заметки и цвета дайджеста не переносятся как новые состояния. Неоднозначные области требуют ручной проверки на тестовой копии.
- Перед рабочим созданием года — проверка на тестовой книге: структура, даты, формулы, ширины, высоты, объединения, защиты и визуальное совпадение с шаблоном. В рамках текущего исследования новая годовая вкладка не создавалась.

## Приёмка календарного адаптера — критерии, не отметка о прохождении

1. На тестовой копии публикация создаёт одну карточку; повтор задачи, тайм-аут и рестарт worker не создают вторую.
2. Даты определяются из числовых значений и формул; блоки разной высоты найдены корректно. Отсутствующая неделя вызывает задачу администратора.
3. Чужой текст, формулы, образец, вспомогательные столбцы, оформление и человеческие заметки сохраняются. Значения и формат вне целевой ячейки сравниваются до и после операции.
4. Правки аудитории из Sheets и бота сходятся к одному состоянию. Разные параллельные правки вызывают видимый конфликт. Собственная запись не инициирует повторную рассылку.
5. Перенос освобождает только прежнюю запись бота. Ручной перенос, удаление метки и исчезновение ячейки не отменяют событие.
6. Первая инициализация цветов не отправляет историю. Новая окраска распознанной встречи уведомляет только её лидеров, повторная сверка не дублирует сообщение; неподтверждённый исторический цвет игнорируется.
7. Недоступность Sheets сохраняет возможность регистрации; восстановление возвращает одну согласованную карточку и понятный статус ошибки.
8. Новый год создаётся повторяемо по утверждённому шаблону с полным покрытием года; старая вкладка, другие вкладки и исторические состояния неизменны. Пограничная дата имеет одну каноническую вкладку.
9. В репозитории и журналах отсутствуют реальные контакты, тексты встреч, закрытые ссылки и идентификаторы рабочих книг.
