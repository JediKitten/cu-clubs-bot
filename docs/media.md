# Баннеры экранов

Активный набор хранится отдельно от зафиксированных legacy-файлов: `src/cu_clubs/media/resources/`. В каталоге ровно 24 изображения. Шесть переданных владельцем баннеров стали активными версиями `auth`, `menu`, `personal-account`, `clubs`, `club-owner` и `events`; ещё 18 переданных PNG добавлены как отдельные роли. Файлы скопированы без изменения байтов. `manifest.json` хранит имя роли, имя файла, SHA-256 и размер; сравнение с пользовательскими оригиналами выполнено перед добавлением. Пути к личным исходникам в репозитории не сохраняются.

Шесть квадратных PNG 5120×5120 превышали суммарный лимит Telegram по ширине и высоте (10 000 px). Для отправки `media.upload_bytes` создаёт в памяти пропорциональную PNG-копию максимум 4000×4000; она не обрезается, не дорисовывается, не записывается поверх оригинала и кэшируется в памяти. При необходимости тот же ограничитель пробует меньшие размеры, сохраняя соотношение сторон. Manifest SHA относится к неизменённому исходнику; `original_bytes` отдаёт именно его, а экранный кэш/file ID использует отправляемую версию.

`media.resolve_banner_role` выбирает баннер по callback, затем по состоянию диалога, затем по подсказке экрана. На неизвестном callback или общей ошибке используется `menu` как общий визуальный fallback. Если экран передаёт собственное фото, адаптер оставляет его без замены; это сохраняет обложки клубов и встреч, а QR остаётся данными QR-сценария. `ScreenManager` распознаёт активные баннеры и повторно загружает их на страницах.

## Инвентарь экранов и арт-ролей

| Арт-роль | Куда назначается |
|---|---|
| `auth` | Вход, подтверждение личности, выбор категории и шаги ввода профиля |
| `menu` | Главное меню и общий fallback для неизвестных действий/ошибок |
| `personal-account` | Личный кабинет и переходы из профиля |
| `clubs` | Каталог, карточки клуба без собственной обложки, подписка и клубные ссылки |
| `club-owner` | Главный экран владельца и основные действия управления клубом |
| `events` | Каталог и просмотр встреч без собственной обложки |
| `calendar` | Календарь, выбор недели и уведомление о встрече в календаре |
| `digest` | Создание дайджеста и предпросмотр поста/карточек |
| `survey_builder` | Список и редактирование вопросов опроса |
| `attendance` | Посещение, списки регистрации и ручная отметка |
| `faq` | Разделы и статьи справки |
| `admin` | Панель администратора и управление доступом |
| `api_clients` | Подключённые боты, их разрешения и управление клиентом |
| `api` | Интеграционная ссылка и экран подключения API |
| `notifications` | Настройка уведомления, текст и предпросмотр рассылки |
| `analytics` | Аналитика, фильтры и отчёты |
| `survey_answer` | Ответ на опрос встречи и приглашение оценить её |
| `rosters` | Реестры участников и списки состава |
| `collaboration` | Совместные встречи и выбор клуба-партнёра |
| `templates` | Шаблоны встреч и их редактирование |
| `club_team` | Просмотр/редактирование публичной команды и списка организаторов |
| `club_settings` | Настройки клуба и пакетное редактирование профиля |
| `event_create` | Создание встречи, черновики и её редактирование |
| `my_events` | Предстоящие встречи пользователя, история и экспорт ICS |

Все перечисленные роли имеют отдельный предоставленный PNG. Отдельных иллюстраций для персональной обложки клуба или встречи нет: используются реальные обложки, если они заданы, и тематические `clubs`/`events` как fallback. QR не оформляется баннером, поскольку само изображение QR содержит данные.

## Проверка

`tests/test_media.py` проверяет 24 роли и их хеши, маршруты callback/state, тематический fallback, загрузку активного изображения, Telegram-лимиты транспортной копии и отказ от неизвестной роли. Проверка хешей фиксирует целостность файлов в пакете; исходные пользовательские файлы в production-пакет не включаются.
