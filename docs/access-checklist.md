# Что нужно предоставить для запуска

Это список входных данных. Реальные пароли, OAuth-токены и ключи не следует
вставлять в этот документ или коммитить. Передача — через игнорируемый `.env`
на целевом сервере либо его хранилище секретов.

## 1. Сервер и домен

- Сервер киноклуба проверен через SSH; повторно присылать доступ не нужно.
- Новый каталог `~/cu-clubs-bot`, отдельный Compose project `cu-clubs-test`.
- PostgreSQL создаётся в собственном контейнере без публичного порта.
- Тестовый Telegram использует polling. HTTPS-маршрут понадобится позже для
  перехода на webhook; общий Caddy пока не изменяется.

Доступы к прочим проектам на сервере не требуются.

## 2. Telegram

- Передан и проверен только тестовый бот `@cu_clubs_app`; пока работаем с ним.
- Числовые ID владельца `@jedi_kitten` и Яси `@yaroslavakir` уже получены и
  сохранены в закрытой конфигурации.
- Обоим администраторам открыть личный диалог с новым ботом через `/start`.
  Это также необходимо для получения резервных копий владельцем.

Права выдаются по numeric ID, а не по изменяемому username. Числовые ID
можно получить из входящего update после запуска тестового бота; сторонний
бот для этого не обязателен.

## 3. Google от личного аккаунта владельца

- Сейчас используется личный аккаунт, позже адаптер переключается на
  отдельный интеграционный аккаунт.
- Для автономной работы сервера нужен OAuth client ID/client secret
  и разрешённый offline-доступ к Google Sheets с refresh token.
  Подключение Google Drive в приложении Codex само по себе не предоставляет
  серверному процессу такие runtime-credentials.
- Понадобится Google Cloud project с включённым Sheets API. Для текущего
  адаптера Drive API и полный Drive scope не требуются.
- Интерактивное согласие выполняется владельцем аккаунта; пароль Google
  приложению не передаётся.
- Для рабочего запуска нужен доступ выбранного аккаунта к календарю.

Тестовая копия уже создана. Её идентификатор хранится в локальной
конфигурации, а не в опубликованных документах. Новый год — новый лист
`Calendar YYYY`, тот же шаблон без смены сетки.

## 4. Почта

- Выбран предлагаемый отправитель `cuclubs@cu3rd.ru` через Resend; адрес пока
  не подключён. Регистрацию аккаунта завершает владелец.
- Далее нужны точные DNS records из панели Resend и подтверждение домена.
- SMTP host/port/TLS известны; после подтверждения нужен Sending API key
  как SMTP password. Ключ сохраняется только в закрытой конфигурации.
- Тестовый студенческий адрес и возможность получить письмо с кодом.

Использование личного Google-аккаунта для Sheets не подразумевает, что он же
может отправлять письма от университетского адреса.

## 5. Первоначальное наполнение

- Уровень киноклуба: Seed, подтверждён владельцем.
- Создаётся минимальная карточка Киноклуба; описание, обложку, команду и ссылки
  владелец дополнит через интерфейс бота.
- ФИО и логин Тайма понадобятся на этапе почтового подтверждения; сам bootstrap
  по прямому решению владельца не блокируется отсутствием email.
- Границы отчётов уже заданы: 1 сентября–31 января; 1 февраля–30 июня;
  лето 1 июня–31 августа. Июнь входит в два независимых отчётных периода.
- Контакт Яси: `@yaroslavakir`; для кнопки используем её Telegram-профиль.

Обязательная карточка клуба входит в первый продуктовый этап независимо от
наличия обложки. Остальные клубы администрация добавит через кабинет.

## 6. Резервное копирование

- Получатель: numeric Telegram ID владельца; ник не используется как адрес.
- Предложенный настраиваемый график: ежедневно в 03:00 Europe/Moscow.
- Worker создаёт PostgreSQL custom dump и ставит его отправку документом в
  outbox. Доставка имеет собственный статус и обработку ошибки.
- Срок хранения: без автоматического удаления по решению владельца.
- Реализация должна учитывать предел размера файла текущего Telegram API;
  не считать неотправленный или неполный файл успешной резервной копией.
- Приёмка включает восстановление копии в изолированной тестовой среде с
  отключёнными рабочими отправителями.
