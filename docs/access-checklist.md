[deployment.md](deployment.md). Секреты передаются в закрытом канале/хранилище,
не в этом документе, Git, issues или сообщениях боту.

## 2. Telegram, идентичность и права

- [ ] Владение/управление тестовым `@cu_clubs_app` у BotFather и закрытый bot token.
- [ ] Текущие numeric admin/leader IDs и список полномочий из БД; bootstrap
  настройки не заменяют фактическую проверку выданных ролей.
- [ ] Возможность у нужных администраторов и получателя backup открыть `/start`.
- [ ] Неизменный `CU_CLUBS_VERIFICATION_SECRET` и webhook secret, даже при polling.
- [ ] Результат сквозной приёмки Яндекса после получения новой ссылки из бота.

Username не выдаёт права. На действующем test включены временные
`TEST_SELF_REGISTRATION_ENABLED` и `TEST_ALLOW_UNVERIFIED_LEADERS`; это
ограниченные тестовые режимы, не доказательство университетской почты и не
политика production. Менять их без решения владельца при передаче нельзя.

## 3. Яндекс OAuth

- [ ] Доступ владельца к приложению CU Clubs в [Яндекс OAuth](https://oauth.yandex.ru/).
- [ ] Право управлять только нужным `login:email`, зарегистрированным redirect
  `https://de.devbox.cu3rd.ru/auth/yandex/callback` и закрытым client secret.
- [ ] Client ID и четыре runtime-переменные сверены без раскрытия secret.
- [ ] Объяснено, что callback готовит кандидата, а профиль подтверждается исходным
  Telegram ID после предпросмотра. Университетский SSO/зачисление тестами не доказаны.

Яндекс включён на прежнем сервере. Self-service использует другую БД и не
получает эти настройки через существующий tag-only helper автоматически.
Подробности — [yandex-login.md](yandex-login.md).

## 4. Google и календарь

- [ ] Владение Google Cloud OAuth project/client и аккаунтом, имеющим доступ
  к тестовой копии календаря. Runtime credentials не равны подключению Drive в Codex.
- [ ] Приватный authorized-user JSON из `google_credentials`, способ безопасной
  замены и отзыва. JSON не входит в PostgreSQL dump.
- [ ] Сверены `GOOGLE_SPREADSHEET_ID`, `CALENDAR_TEST_SPREADSHEET_ID`, лист
  `Calendar YYYY`, OAuth mode и разрешённая тестовая книга.
- [ ] Проверен срок/отзыв refresh token и, при необходимости, выполнена новая
  авторизация владельцем. В External + Testing требуется регулярное обновление.
- [ ] Отдельно приняты чтение и календарная запись: наличие файла не доказывает
  refresh, а чтение метаданных не доказывает сохранение шаблона при записи.

В текущем test календарная синхронизация и запись включены, target совпадает
с разрешённой тестовой копией, credential file существует. При передаче 22 ноября
новый запрос Google/refresh не выполнялся. Sheets API достаточно текущему
адаптеру; Drive API/полный Drive scope не обязательны.

## 5. SMTP — отложенная интеграция

SMTP на действующем сервере не настроен; Яндекс-вход не требует SMTP.
`cuclubs@cu3rd.ru`/Resend — прежнее предложение, а не подключённый отправитель.
Если почта понадобится: согласовать владельца домена, точные DNS из панели,
Sending API key, host/port/TLS/From и один адрес приёмки. Не переносить в новую
среду выдуманные DKIM/MX или обычный пароль Google. Инструкция —
[integrations-setup.md](integrations-setup.md); прежние тарифы заново не проверены.

## 6. Резервные копии и восстановление

- [ ] Доступ к backup-томам/архивам, numeric получатель и подтверждённая доставка.
- [ ] Сохранены закрытые конфигурации и Google credentials отдельно от dump.
- [ ] Принимающая команда восстановила копию в изолированной БД с выключенными
  рабочими отправителями и сверила схему/таблицы/контрольные данные.
- [ ] Определены ёмкость, наблюдение за ошибками и политика хранения: автоматического
  удаления сейчас нет; файлы больше 49 MiB не отправляются адаптером Telegram.

На сервере backups включены: `0 3 * * *`, Europe/Moscow. Статус отправки и
создание dump — разные проверки. Первое восстановление 12 ноября историческое
и не доказывает восстановление последнего файла. Backup-документ остаётся
в Telegram при последующей навигации.

## 7. Self-service — только при продолжении переноса

- [ ] Права на проект/namespace, registry, SSH gateway и managed PostgreSQL.
- [ ] Текущие platform mappings, sealed secrets и release перечитаны без вывода значений.
- [ ] Условия CI/registry/OIDC/delivery credentials подтверждены отдельно от GitHub.
- [ ] Yandex mappings добавлены штатно, доступ к нужному callback принят.
- [ ] Пока нет финального dump/restore/сверки и остановки старого poller,
  `SELF_SERVICE_WORKER_ENABLED=false` сохраняется.

Новая команда не должна считать настройку платформы завершённой миграцией.
[План переключения и отката](self-service-migration.md).
