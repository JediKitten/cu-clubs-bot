## Реализовано и установлено

Совпадение модулей подтверждает наличие кода. Оно не заменяет ручную приёмку
каждой роли, интеграции или стороннего плагина.

| Блок | Реализованное поведение | Ограничение / приёмка |

| Встречи | Черновики, публикация, перенос/отмена, контакт, коллаборации и подтверждения | Повторно принять изменение, отмену и согласие партнёра живыми пользователями |
| Шаблоны | Карточки, редактирование, предпросмотр, перенос даты, переименование и удаление | Существующие встречи не меняются; проверить роль соорганизатора |

## Последние исправления и доказательства

- `dc566ea`: обычная навигация во время Яндекс-входа больше не попадает в
  проверку устаревшего `ya:*` nonce; 16 целевых проверок прошли в предыдущем пакете.
- `b6d4531`: отсутствующий необязательный `scope` в ответе Яндекса принимается,
  явно недостаточные права отклоняются. Диагностика не пишет токены, code или email.
  Первый запрос после копии переносит меню вниз. Семь auth и восемь menu проверок
  прошли; независимые compatibility/UX review одобрили итоговый diff.
- Эти числа — результаты соответствующих пакетов. Полный набор тестов 22 ноября
  повторно не запускался. Исторические 392/397/540 не являются числом текущего прогона.
- Последняя отправка кода в GitHub успешна, в Forgejo по SSH — неуспешна.
  Release overlay и текущий образ находятся на действующем сервере, не в Git.

## Открыто для новой команды

Приоритеты здесь не назначены; их определяет владелец.

1. Повторить вход университетским аккаунтом по новой ссылке и подтвердить
   привязку в Telegram; принять поведение меню после реальной копии.
2. Выполнить краткую ролевую приёмку установленных функций: студент, гость,
   лидер, организатор, администратор, партнёр коллаборации.
3. Согласовать рабочий режим и отключение тестовых исключений с владельцем;
   не отключать их без проверки доступов уже созданных пользователей.
4. Подтвердить refresh Google OAuth, тестовую синхронизацию, границы года,
   конфликты и разрешение на подключение рабочего календаря.
5. Настроить публичный HTTPS API действующей БД и принять интеграцию внешних
   клиентов, включая согласие, отзыв, повторы и webhooks.
6. Передать секреты/серверный overlay отдельно, проверить доступы новой команды,
   сделать и восстановить новую копию в изолированную БД, настроить оповещения.
7. Восстановить доступ/синхронизацию Forgejo и подготовить воспроизводимый полный
   образ из Git. Не возобновлять перенос в self-service как побочный шаг передачи.
8. Устранить неполноту OpenAPI EventOutput: HTTP JSON содержит `public_id`,
   поля площадки/лимитов/техники и timestamps, которых нет в схеме генератора
   клиента. Значения не теряются в HTTP; проблема в описании контракта.
9. Доработать CalendarSync: создание `Calendar YYYY`, расширение недель,
   последнюю неделю без следующего заголовка (`unbounded_week`), защиту
   конкурентных Google-правок. `CALENDAR_DIGEST_COLOR` пока не меняет
   жёстко заданный `#FF00FF`; объявленная настройка не равна работающей функции.
10. Сверить FAQ с текущим Яндекс-сценарием и продуктовые правила; принять Figma
   в настоящем редакторе с нужным шрифтом.

SMTP и автоматическая публикация дайджеста — отдельные задачи. Расширенный
дайджест (состояние недели, историческая инициализация, поздняя публикация,
настройки цвета) остаётся отдельным согласованием/доработкой.
Mini App, перенос старой базы, серии встреч, лист ожидания, финансы,
автобронирование помещений и физические пропуска в согласованную v1 не входят.
