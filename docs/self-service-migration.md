# Перенос CU Clubs в self-service cu3rd

Сверка: 15 ноября 2026. Перенос разрешён владельцем. Рабочий бот до
проверенного переключения остаётся на прежнем сервере; это документ переноса,
а не подтверждение уже состоявшегося переключения.

## Целевая конфигурация

- Исходники: https://git.cu3rd.ru/Jedi_kitten/cu-clubs-bot, ветка `main`.
- Проект `cu-clubs-bot`, окружение `test`, зона `xgrm`, один экземпляр `api`.
- Образ собирается с `--target selfservice`; обычная сборка сохраняет прежний
  запуск Compose и системного пользователя для существующих томов.
- PostgreSQL управляется платформой; адаптер отключает prepared statements
  и ограничивает пул двумя соединениями на процесс для transaction PgBouncer.
- Запрошенный адрес: `https://clubs-api.cu3rd.ru`. Платформа создаёт DNS,
  ingress и сертификат. До внешней проверки TLS этот адрес не является рабочим.
- `Recreate`, одна реплика, `/data` — постоянный том 4 GiB: резервные копии,
  приватный файл настроек, Google credentials и ключ SSH-сервера.
- SSH только через шлюз: `ssh -p 8222 cu-clubs-test@ssh.cu3rd.ru`.
  В конфигурации указан существующий публичный ключ владельца; root,
  пароли, перенаправление портов и агент SSH запрещены.
- SMTP не подключается, категории без почты сохраняются. Студент/сотрудник
  обязательно указывают ФИО и логин Тайма и подтверждают данные.

Регистрация и первая доставка проходят обязательное SRE review платформы.
Готовый пример — `deploy/self-service-project.yaml`. Источники правил:
[платформа](https://git.cu3rd.ru/cu3rd/self-service),
[шаблон](https://git.cu3rd.ru/cu3rd/self-service-template), проверены по
`52e5e58342d6af391c8cbb98710215289f5e052d` и `4ead34b` соответственно.

## Секреты и последующие выпуски

Первоначальная доставка шифруется публичным сертификатом платформы, строго
для namespace `cu3rd-cu-clubs-bot-test` / Secret `cu-clubs-bot-test-api-env`.
Токен бота, webhook secret, прежний verification secret, Google OAuth JSON,
ID тестовой таблицы и получатель копий не попадают в открытые env или образ.
Verification secret сохраняется дословно: иначе нельзя расшифровать inbox,
идемпотентные ответы и секреты подписей webhook.

Для следующих автоматических доставок репозиторию нужны Actions Secrets и
Variables, перечисленные в mappings проекта, плюс
`SELF_SERVICE_DELIVERY_TOKEN` от платформы (только предложение PR, без
обхода защиты master). Публикация использует `REGISTRY_USER`/`REGISTRY_TOKEN`,
если они заданы; иначе проверяется штатный временный token собственного job.
Доступ пакета для чтения кластером проверяется отдельно. Автодоставка включается
переменной `SELF_SERVICE_DELIVERY_READY=true` только после добавления всех mappings
и ограниченного токена; первоначальная доставка проходит вручную через PR №204. Файлы с расшифрованными
настройками хранятся только в игнорируемом `.cache` с правами 0600.

## Порядок переключения

1. Проверить сборку, тесты и восстановление отдельной копии БД. Опубликовать
   неизменяемый образ с SHA commit. Проверить проект и ciphertext платформенным
   валидатором. Дождаться SRE merge и готовности staged экземпляра.
2. Первая доставка обязательно содержит `SELF_SERVICE_WORKER_ENABLED=false`:
   новый экземпляр не читает Telegram, не отправляет outbox и не пишет Sheets.
   Автоматического bootstrap клуба или назначения ролей нет.
3. Проверить SSH, DNS, HTTPS, `/health/live`, `/health/ready`, OpenAPI и отказ
   неавторизованному запросу. Это ещё не подтверждение переноса данных.
4. Остановить **оба** старых процесса API/worker, запретить их автоматический
   рестарт на время переключения. Сделать окончательный `pg_dump` и сохранить
   старые тома и настройки. Сравнить размеры, schema revision, число записей
   всех прикладных таблиц и хеши контрольных данных без публикации персональных данных.
5. Перенести dump и все прежние backup-файлы в `/data`, сохранив их без удаления.
   Через SSH выполнить `python /app/deploy/ops.py restore /data/final.dump`,
   затем `python /app/deploy/ops.py migrate`. Restore использует одну транзакцию,
   `--no-owner --no-acl --clean --if-exists`, без создания БД. С включённым worker
   restore запрещён. Не отправлять коды/уведомления на пробной копии.
6. После совпадения данных и проверки Google credentials отдельной доставкой
   включить worker. Проверить heartbeat, отсутствие второго poller, ошибки,
   календарь, очереди, личный кабинет, API 401/согласие и резервное копирование.
   Новые API scopes, регистрация и проверки согласия не ослабляются из-за HTTPS.
7. Обновить актуальный статус, карту UX и обе инструкции API настоящим адресом
   и результатами приёмки. Старые контейнеры оставить остановленными, данные сохранить.

При неудаче до приёма новых записей остановить новый worker, вернуть старые
процессы на финальном исходном состоянии. После приёма новых записей сначала
нужно вернуть свежую БД с новой площадки; нельзя запускать устаревшую копию.

## Ограничения начального переноса

Supervisor завершает остальные процессы при выходе одного и передаёт SIGTERM.
Отдельного автоматического обнаружения зависшего worker по heartbeat пока нет;
при приёмке проверяется его heartbeat и очередь. Платформенная HTTP-проба
проверяет API и соединение с БД, а не все внешние интеграции.

## Повтор переноса после готовности платформы

15 ноября source run №6 прошёл 397 тестов, lint/format и проверку 25 API-маршрутов.
Образ `4815914cf6af2a5800b7a0b384055139fa260387` собран
(`sha256:d8a147113541b7021916a52cbb6ca694e89cf951ddfaa9990d853159e5ce076f`),
но загрузка временным job token завершилась `unauthorized: reqPackageAccess`.
Владелец разрешил создание `cu-clubs-registry-publisher`: `write:package` /
Public only, без доступа к коду и аккаунту. Ключ создан и сохранён только
в Actions Secret `REGISTRY_TOKEN` CU Clubs; source run №6 запущен повторно.
Права Forgejo на пакеты не ограничиваются одним пакетом, что согласовано
владельцем; само значение не хранится в исходниках или документации.

[PR №206](https://git.cu3rd.ru/cu3rd/self-service/pulls/206) меняет только tag
проверенного приложения; `SELF_SERVICE_WORKER_ENABLED=false`, mappings и
шифрованные настройки сохраняются. Валидатор платформы прошёл для 19 проектов
и всех доставок. До публикации образа и принятия PR перенос не завершён.

Повтор run №6 остановился до тестов при установке wheel: `No space left on
device` на CI-раннере. В workflow очищаются списки apt и download-cache pip;
uv-cache перенесён на один том с `.venv` с hardlink, чтобы не хранить вторую
копию каждого установленного пакета. Это изменение только сборки; результат
первой полной проверки 397 тестов сохраняется как отдельное свидетельство,
но успешная публикация нового выпуска ещё обязательна.
