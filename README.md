# CU Clubs Bot

Университетский Telegram-бот клубов ЦУ и API для клубных ботов.

## Текущее состояние

Первый рабочий срез: PostgreSQL и миграции, создание киноклуба и двух
администраторов, каталог и карточка клуба, подписки, редактирование карточки с
предпросмотром, независимые публичная команда и права организаторов.
Диалоги и входящие обновления сохраняются в БД; отдельный worker обрабатывает
обновления, отправляет уведомления и ежедневные резервные копии.

Встречи, регистрация на них, QR посещения, опросы и аналитика остаются следующими
этапами. SMTP и личный Google OAuth имеют готовые адаптеры и инструкцию, но
требуют настройки аккаунтов владельцем. Наличие настройки не означает подключения.

## Согласованный объём

- В первом продуктовом этапе: карточка клуба, каталог, почтовая верификация,
  роли и кабинет администрации.
- Далее: встречи, коллаборации, запись, API, синхронизация существующего
  календаря Google Sheets, QR, ведомости, опросы и аналитика.
- Новая база, два администратора и один стартовый киноклуб.
- Данные без автоматического удаления. Предусмотрена ежедневная резервная
  копия в личный Telegram-чат владельца от имени бота.
- Каждый календарный год использует отдельный лист `Calendar YYYY`;
  оформление существующего календаря сохраняется.

## Локальный запуск

Требуется Python 3.12 и uv.

```sh
uv sync --locked
cp .env.example .env
uv run python -m cu_clubs api
```

Адрес приложения — `http://127.0.0.1:8000`, схема OpenAPI — `/openapi.json`.
Проверка liveness не требует внешних сервисов, readiness проверяет доступность
PostgreSQL. Без подключённой БД отрицательный результат readiness ожидаем.

Проверки проекта:

```sh
uv run pytest
uv run ruff check .
```

Для миграций, первоначального создания клуба и процессов:

```sh
uv run cu-clubs migrate
uv run cu-clubs bootstrap
uv run cu-clubs worker
```

`bootstrap` требует numeric ID администраторов и лидера в окружении.
`worker` требует явно включённой внешней доставки, токена выбранного бота и его
username. Он проверяет соответствие токена username перед работой. Для webhook
нужны HTTPS-маршрут и команда `uv run cu-clubs webhook`. На тестовом сервере
пока используется polling без изменений общего Caddy.

Точные команды контейнерного запуска и переменные доступны в `compose.yaml`
и `.env.example`. Рабочие секреты хранятся вне Git. По умолчанию внешняя
доставка отключена; локальное приложение не отправляет письма, сообщения
и изменения в рабочий календарь.
