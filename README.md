## Что работает

Тестовый бот [@cu_clubs_app](https://t.me/cu_clubs_app) обслуживается прежним
сервером; self-service не является действующим экземпляром этого бота.
Каталог, карточки клубов, независимые публичная команда и права организаторов,
встречи и коллаборации, шаблоны, календарь/история/ICS, запись и отмена,
QR и XLSX-посещения, опросы, аналитика, уведомления, FAQ и экспорт дайджеста
реализованы и присутствуют в установленном Python-коде.

Вход через Яндекс включён, SMTP не настроен. Для студентов и сотрудников
проверяется университетский `default_email` с доменом `edu.centraluniversity.ru`.
Сквозная приёмка входа владельцем после последнего исправления ещё не зафиксирована.
Включены тестовые исключения регистрации и назначения неподтверждённых лидеров:
это не подтверждение университетской почты и не готовая политика production.
Синхронизация Google Sheets включена только для разрешённой тестовой копии;
живой refresh при сверке документации не проверялся.
API доступен на серверном loopback; публичный HTTPS для внешних клубных ботов
не подтверждён. HTTPS под `de.devbox.cu3rd.ru` обслуживает OAuth, не весь API.

Интерфейс сохраняет один текущий экран. После доставленной резервной копии
первое действие переносит меню вниз, сохраняя файл копии.

## Локальный запуск

Требуются Python 3.12, uv и PostgreSQL 17. Команды выполняются из корня проекта.
На чистой машине с незанятым локальным портом 5432:

```sh
uv sync --locked
cp .env.example .env
docker compose up -d db
uv run cu-clubs migrate
uv run cu-clubs api
```

Не заменяйте существующий `.env` этой командой копирования. Пример использует
локальные учётные данные из `compose.yaml`; это не серверная конфигурация.
API: `http://127.0.0.1:8000`, OpenAPI: `/openapi.json`, Swagger: `/docs`.
`/health/live` проверяет процесс, `/health/ready` — доступность PostgreSQL.
Начальные роли и клуб создаёт отдельная команда `uv run cu-clubs bootstrap`
после задания числовых ID администраторов и лидера.

Для живой Telegram-доставки нужен отдельный процесс `uv run cu-clubs worker`
и явно включённые настройки доставки. Не запускайте второй polling worker
с токеном работающего бота. На локальной конфигурации внешняя доставка выключена.

## Проверки

Для документации достаточно `uv run python scripts/check_api_docs.py` и проверки
ссылок. Полная проверка кода выполняется в отдельной тестовой БД:

```sh
uv run ruff check .
uv run ruff format --check .
uv run python scripts/check_api_docs.py
# Задайте TEST_DATABASE_URL, указывающий только на выделенную тестовую PostgreSQL.
uv run pytest
```

Без `TEST_DATABASE_URL` часть интеграционных тестов пропускается; такой запуск
не подтверждает полный набор. Тесты создают/очищают таблицы и не должны использовать
рабочую БД. CI описан в `.github/workflows/ci.yml` и `.forgejo/workflows/publish.yml`.
Текущая проверка документации не запускает полную сборку и весь набор тестов.

## Совместимость и ресурсы

`3a09cc0039d86641827dcbc28e74dd024b821732`. Исходные тексты и шесть закреплённых
legacy-баннеров хранятся в `src/cu_clubs/legacy/resources/`. Активный интерфейс

`src/cu_clubs/media/resources/`; их байты и авторские отметки сохраняются.
[Карта совместимости](docs/legacy-compatibility.md), [правила медиа](docs/media.md),
[инструкции для разработки](AGENTS.md).

в Git. Два исходных ТЗ с внутренними ссылками локальны и исключены из Git;
получение этих материалов отдельно согласуется с владельцем. Для передачи
по репозиторию используйте актуальные решения, статус и документ передачи.
