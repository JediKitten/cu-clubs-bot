# CU Clubs Bot

Университетский Telegram-бот клубов ЦУ и API для клубных ботов.

## Текущее состояние

Тестовый бот: каталог и карточки клубов, подписки, независимые публичная команда
и права организаторов. Интерфейс работает в одном сохраняемом сообщении.
Реализованы почтовая верификация, административные команды, черновики и публикация
встреч, недельный список, запись/отмена, переносы, коллаборации и шаблоны.
Диалоги и зашифрованные входящие обновления сохраняются в PostgreSQL; worker
доставляет уведомления и ежедневные резервные копии.

Отправитель SMTP ещё не настроен, поэтому реальное подтверждение почты пока
недоступно. Личный Google OAuth подключён, но синхронизация Sheets, QR посещения,
опросы, аналитика и публичный интеграционный API остаются следующими этапами.
Подробные границы: [пакет 13 ноября](docs/release-2026-11-13.md).

Шаблоны имеют отдельные карточки, редактирование с предпросмотром,
переименование и удаление с подтверждением. Для новой встречи можно выбрать
только дату, сохранив время начала и длительность; ранее созданные встречи
не меняются. Команды соорганизаторов сохраняют копии в шаблоны своих клубов.

## Согласованный объём

- В первом продуктовом этапе: карточка клуба, каталог, почтовая верификация,
  роли и кабинет администрации.
- Далее: встречи, коллаборации, запись, API, синхронизация существующего
  календаря Google Sheets, QR, ведомости, опросы и аналитика.
- Новая база, два администратора и один стартовый киноклуб.
- Данные без автоматического удаления. Предусмотрена ежедневная резервная
  копия в личный Telegram-чат владельца от имени бота.
- Каждый календарный год использует отдельный лист `Calendar YYYY`;
  оформление существующего календаря сохраняется.

## Совместимость

Проект перерабатывает `nlypage/cu-clubs-bot` версии `3a09cc0`. В одинаковых сценариях
используются исходные тексты и изображения. Каталог из 214 строк, исходная разметка
и оригинальные ресурсы закреплены в `cu_clubs.legacy`; новые функции дополняют эти
блоки. Шесть экранных баннеров получены от владельца. Баннер главного меню заменён
новым файлом по отдельному указанию владельца; исходник и копия для Telegram сохранены.
Независимый агент `legacy_compatibility_guard` проверяет каждый такой выпуск.

Исходные спецификации сохраняются локально в `docs/development-spec.md` и
`docs/specification.md`. Они исключены из Git: содержат внутренние ссылки.

## Локальный запуск

Требуется Python 3.12 и uv.

```sh
uv sync --locked
cp .env.example .env
uv run python -m cu_clubs api
```

Адрес приложения — `http://127.0.0.1:8000`, схема OpenAPI — `/openapi.json`.
Проверка liveness не требует внешних сервисов, readiness проверяет доступность
PostgreSQL. Без подключённой БД отрицательный результат readiness ожидаем.

Проверки проекта:

```sh
uv run pytest
uv run ruff check .
```

Для миграций, первоначального создания клуба и процессов:

```sh
uv run cu-clubs migrate
uv run cu-clubs bootstrap
uv run cu-clubs worker
```

`bootstrap` требует numeric ID администраторов и лидера в окружении.
`worker` требует явно включённой внешней доставки, токена выбранного бота и его
username. Он проверяет соответствие токена username перед работой. Для webhook
нужны HTTPS-маршрут и команда `uv run cu-clubs webhook`. На тестовом сервере
пока используется polling без изменений общего Caddy.

Точные команды контейнерного запуска и переменные доступны в `compose.yaml`
и `.env.example`. Рабочие секреты хранятся вне Git. По умолчанию внешняя
доставка отключена; локальное приложение не отправляет письма, сообщения
и изменения в рабочий календарь.
